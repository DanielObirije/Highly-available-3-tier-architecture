# AWS 3-Tier Architecture with Terraform

This project provisions a small, multi-AZ AWS environment using Terraform. It separates the workload into public web, private application, and private database tiers to demonstrate network isolation, load balancing, and Auto Scaling.

## Architecture

![AWS 3-tier architecture](<highly available 3-tier AWS architecture-1.png>)

The deployment uses a VPC with CIDR `10.0.0.0/16` across two Availability Zones:

- **Web tier:** Two public subnets host an internet-facing Application Load Balancer and an Auto Scaling group of Ubuntu EC2 instances.
- **Application tier:** Two private subnets host an internal Application Load Balancer and a separate Auto Scaling group of Ubuntu EC2 instances.
- **Database tier:** Two private subnets are used by an encrypted MySQL 8.0 RDS instance through a DB subnet group.

### Traffic flow

1. Internet traffic reaches the public web ALB on HTTP port 80.
2. The web ALB forwards requests to the web Auto Scaling group.
3. The application tier has its own internal ALB and target group for private HTTP traffic.
4. RDS accepts MySQL traffic on port 3306 only from the application security group.
5. Private application instances use a NAT Gateway in a public subnet for outbound internet access, such as package installation during bootstrapping.

## What Terraform Creates

- A VPC, Internet Gateway, public and private route tables, and subnet associations.
- Two public web subnets, two private application subnets, and two private database subnets.
- A NAT Gateway with an Elastic IP for application subnet egress.
- Separate security groups for the web, application, and database tiers.
- Public and internal Application Load Balancers with HTTP listeners and health checks.
- Web and application launch templates that install Apache and publish the instance Availability Zone.
- Web and application Auto Scaling groups with a desired capacity of two and CPU target tracking at 50%.
- An encrypted, non-public MySQL 8.0 RDS instance using `gp3` storage.
- An RSA key pair generated by Terraform and saved locally as a sensitive `.pem` file.

## Repository Structure

```text
provider.tf            # Terraform and AWS provider requirements
variables.tf           # Input variables and default network layout
vpc.tf                 # VPC, subnets, route tables, and associations
nat-gateway.tf         # NAT Gateway and Elastic IP
security-groups.tf     # Web, application, and database access rules
key-pair.tf            # EC2 key pair and local private key
ami.tf                 # Ubuntu AMI data source
launch-templates.tf   # EC2 configuration and bootstrap scripts
target-groups.tf      # ALB target groups and health checks
load-balancers.tf     # Public web ALB and internal app ALB
autoscaling.tf         # Auto Scaling groups and scaling policies
rds.tf                 # DB subnet group and MySQL RDS instance
outputs.tf             # Useful deployment outputs
```

## Requirements

- An AWS account with permissions to create the resources above
- AWS CLI with credentials configured
- Terraform 1.5 or later

Verify the local tools and credentials:

```bash
terraform version
aws sts get-caller-identity
```

## Deploy

```bash
terraform init
terraform validate
terraform plan
terraform apply
```

After applying, retrieve the public web endpoint:

```bash
terraform output -raw web_alb_dns_name
```

The internal application ALB DNS name, RDS endpoint, and NAT Gateway public IP are also available through Terraform outputs.

## Destroy

This project is intended as a demonstration environment. Remove its resources when they are no longer needed:

```bash
terraform destroy
```

## Current Design Notes

- The web and application instances currently serve simple Apache pages for tier and Availability Zone verification; this is not a complete business application.
- The RDS instance is private but is configured with `multi_az = false`, no backup retention, and deletion protection disabled to keep the example lightweight.
- The environment uses one NAT Gateway in the first public subnet, so NAT egress is not fully redundant.
- Review the SSH ingress rule and restrict it to a trusted CIDR before using this configuration outside a lab environment.
